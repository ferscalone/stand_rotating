# Веб-панель стенда вращения

Панель вращающегося стенда ESP32-S3 (`../firmware`). Устроена так же, как панели
стендов press/bend (`server/dashboard1`, `server/dashboard2`): Vite + React +
TypeScript, uPlot, тёмная/светлая тема, канал управления и журнал на маленьком
Node-сервере без зависимостей. Стенд - сервер (REST + WebSocket), панель - клиент.

## Что на экране

| Карточка | Что делает |
|---|---|
| Канал управления | кто управляет стендом; занять / освободить / попросить / передать |
| Статус | состояние, причина аварии, фаза программы, драйвер вкл/выкл |
| Вращение | фактическая скорость, ротор с меткой угла внутри оборота, полные обороты (кнопка «Обнулить»), позиция, пробег |
| Ток (INA219) | ток, напряжение, мощность, загрузка относительно порога аварии |
| Датчики Холла · контроль вращения | по каждому датчику: обороты, скорость, разница со скоростью двигателя, смещение вала, «плохих» подряд, магнит у датчика; сдвиг между концами вала; кнопка автостопа (выключение - вторым нажатием) и последнее предупреждение |
| Ручное управление | направление, скорость (поле + ползунок), непрерывно / N оборотов; на ходу - «Сменить скорость» / «Применить на ходу» |
| Остановка | STOP (плавно по рампе), E-STOP (сразу, без рампы), RESET (сброс аварии) |
| Программа в стенде | загруженная программа, цикл/модуль, обороты модуля, общий прогресс; пуск / пауза / продолжить / стоп |
| Параметры стенда | ускорение рампы (об/мин за с), порог тока, удержание вала в простое; какие датчики Холла в контроле, допуск, мин. ток при вращении |
| Конструктор программ | модули, циклы, оценка времени, загрузка в стенд, общая библиотека |
| Скорость и ток во времени | график ~3 мин: скорость двигателя (со знаком: + по часовой), скорость по датчикам №1/№2, ток |
| Журнал событий | события стенда, предупреждения, команды, действия других операторов; «Испытания и отчёты», «Архив журналов» |

E-STOP работает **без права управления**: остановить вал должен мочь любой, кто
видит панель. Остальные команды уходят только от владельца канала.

## Конструктор программ

Программа - это список **модулей**, который повторяется заданное число **циклов**.
Модуль: направление (↻ CW / ↺ CCW), сколько оборотов, скорость (об/мин), пауза
после модуля (с). Модули добавляются (`+ Модуль` копирует последний,
`+ Туда-обратно` добавляет пару CW/CCW с паузами), переставляются ↑↓,
дублируются ⧉ и удаляются ✕.

- **Склейка**: модуль с паузой 0, за которым идёт модуль в ту же сторону (в том
  числе первый модуль следующего цикла), помечен «⟶» - стенд проходит границу без
  остановки, плавно меняя скорость. Так собираются профили скорости.
- **Полоса цикла** показывает модули в масштабе времени (синий - CW, зелёный - CCW,
  штриховка - паузы). Сводка - обороты за цикл (по направлениям), всего, оценка
  длительности цикла и программы с учётом рампы.
- **Загрузить в стенд** / **Загрузить и запустить** - программа уходит в стенд
  (`POST /v1/program`) и хранится в его памяти; возможно только когда вал стоит.
  Тег «загружена в стенд» показывает, что открытая программа совпадает с
  загруженной.
- **Библиотека** - общая для всех операторов (на сервере панели, файл
  `data/programs.json`): открыть, сохранить, сохранить как новую, удалить (с
  подтверждением). Плюс экспорт/импорт JSON и «Открыть из стенда».
- Черновик живёт в браузере (`localStorage`) и переживает перезагрузку страницы.

Проверки повторяют прошивку: до 64 модулей, 0,01…1 000 000 оборотов,
0,1…200 об/мин, пауза до 1 часа, до 1 000 000 циклов.

## Датчики Холла и автостоп

Прошивка сверяет каждый датчик с шагами двигателя (подробно - `firmware/README.md`).
При расхождении, молчащем датчике или «нет тока при вращении»:

- **автостоп включён** (по умолчанию) - авария, стенд встаёт без рампы, в «Статусе» -
  причина («Датчик Холла №1 не совпадает с двигателем…»), выход - RESET;
- **автостоп выключен** - стенд продолжает работу, в журнал и в карточку датчиков
  приходят предупреждения (не чаще раза в 5 с на вид).

Автостоп переключается кнопкой в карточке датчиков в любой момент, в том числе на
ходу (команда `guard on|off`); выключение - вторым нажатием. Нужно право управления.
Какие датчики в контроле, допуск и минимальный ток - в «Параметрах стенда» (когда
вал стоит).

## Испытания, запись телеметрии и отчёты

**Регистратор.** Сервер панели сам подключается к стенду по WebSocket и пишет
телеметрию, события и испытания - даже когда ни одна панель не открыта. Стенд
начинает писаться, как только его открыли в панели (и после перезапуска сервера
продолжает), или если он указан в `RECORD_HOSTS`. Регистратор занимает одно из 4
подключений стенда.

**Испытание** - прогон от пуска (ручного или программы) до возврата в покой или
аварии. Для каждого записываются все кадры телеметрии (~5 в секунду: скорость
заданная / двигателя / датчиков, ток, напряжение, обороты, цикл, модуль), события и
статистика. Файлы - `logs/runs/<id>.json` (сводка, события) и `<id>.jsonl` (кадры).

Кнопка **«Испытания и отчёты»** (над журналом):

- список испытаний стенда с итогом и суммами (число, обороты, часы работы, аварии);
- **отчёт**: длительность, обороты по двигателю и по каждому датчику, средняя и
  максимальная скорость, расхождение датчиков с двигателем на установившейся
  скорости, макс. смещение вала, ток, энергия, циклы, предупреждения; графики
  скорости, тока/напряжения и нарастающих оборотов; события; примечание (образец,
  условия);
- **CSV** - все кадры для Excel («;», десятичная запятая), **Печать / PDF** - отчёт
  на A4 через печать браузера.

Суточный журнал телеметрии (`logs/<дата>/telemetry_<стенд>.jsonl`, раз в секунду) и
журнал событий - как раньше, в «Архиве журналов».

## Адрес стенда

Как у других панелей: поле в шапке → `localStorage["rotate.stand_host"]` →
`VITE_STAND_HOST` из `.env` → `1.rotate.esp32-s3.local`. Если `.local` не
резолвится, впишите IP стенда (печатается в Serial при загрузке).

## Разработка и проверка без железа

```bash
npm install
```

```bash
npm run dev
```

Панель - `http://localhost:5175` (API координации встроен в dev-сервер Vite).
Для проверки без стенда есть симулятор с тем же протоколом (рампа, программы,
склейка, пауза, ток, датчики Холла и автостоп):

```bash
npm run sim
```

и в шапке панели адрес `localhost:8090`. Неисправности для проверки автостопа:

```bash
curl -X POST "localhost:8090/sim/fault?stall=1"
```

(`stall=1` - вал заклинило, `dead1=1` / `dead2=1` - датчик молчит, `nocurrent=1` -
пропал ток; без параметров - всё исправно).

## Сервер координации

`server/api.mjs` - тот же канал управления и журнал, что у dashboard1/2, плюс
библиотека программ:

- `GET /api/programs` - список;
- `POST /api/programs` - `{ program: {id?, name, cycles, modules}, user, host }`
  (с `id` - обновить, без - создать);
- `DELETE /api/programs/<id>?user=&host=`.

Сохранение и удаление пишутся в общий журнал и видны другим операторам стенда.

Испытания и регистратор:

- `GET /api/runs?host=` - список испытаний (и идущее);
- `GET /api/runs/<id>` - сводка, статистика, события;
- `GET /api/runs/<id>/samples?max=4000` - кадры (с прореживанием, пики сохраняются),
  `?format=csv` - все кадры в CSV;
- `POST /api/runs/<id>/note` - `{ note, user }`; `DELETE /api/runs/<id>?user=&host=`;
- `GET /api/recorder` - какие стенды пишет сервер; `POST /api/recorder` - `{ host }`
  (`enabled: false` - перестать).

Переменные окружения - как у dashboard1/2, плюс:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DATA_DIR` | `./data` | библиотека программ, список стендов регистратора |
| `RECORDER` | `1` | регистратор сервера (0 - выключить) |
| `RECORD_HOSTS` | пусто | стенды, которые писать всегда (через запятую, IP) |
| `RECORD_AUTO` | `1` | писать любой стенд, открытый в панели |
| `RUN_SAMPLE_MS` | `0` | шаг записи кадров испытания (0 - каждый, ~5 Гц) |
| `RUN_RETENTION_DAYS` | `0` | сколько дней хранить испытания (0 - всегда) |
| `SHAFT_STEPS_PER_REV` | `3200` | реальных импульсов на оборот, если прошивка не сообщает |

## Соответствие прошивке

Обороты в прошивке - в её единицах (800 импульсов), панель и сервер переводят их в
реальные (`src/units.ts`, `server/runs.mjs` → `toShaftUnits`) по `steps_per_rev` и
`shaft_steps_per_rev` из телеметрии. Данные датчиков Холла уже реальные.

`src/types.ts` повторяет JSON `firmware/src/Telemetry.cpp`, `src/standLogic.ts` -
переходы `Controller.cpp`, `src/config.ts` (`LIMITS`) и `programLogic.ts` - пределы
`Config.h`. При изменении прошивки эти места держать в синхроне. Симулятор
`tools/stand-sim.mjs` - тоже.
