# Веб-панель стенда вращения

Панель вращающегося стенда ESP32-S3 (`../firmware`). Устроена так же, как панели
стендов press/bend (`server/dashboard1`, `server/dashboard2`): Vite + React +
TypeScript, uPlot, тёмная/светлая тема, канал управления и журнал на маленьком
Node-сервере без зависимостей. Стенд - сервер (REST + WebSocket), панель - клиент.

## Что на экране

| Карточка | Что делает |
|---|---|
| Канал управления | кто управляет стендом; занять / освободить / попросить / передать |
| Статус | состояние, причина аварии, фаза программы, драйвер вкл/выкл |
| Вращение | фактическая скорость, ротор с меткой угла внутри оборота, полные обороты (кнопка «Обнулить»), позиция, пробег |
| Ток (INA219) | ток, напряжение, мощность, загрузка относительно порога аварии |
| Ручное управление | направление, скорость (поле + ползунок), непрерывно / N оборотов; на ходу - «Сменить скорость» / «Применить на ходу» |
| Остановка | STOP (плавно по рампе), E-STOP (сразу, без рампы), RESET (сброс аварии) |
| Программа в стенде | загруженная программа, цикл/модуль, обороты модуля, общий прогресс; пуск / пауза / продолжить / стоп |
| Параметры стенда | ускорение рампы (об/мин за с), порог тока, удержание вала в простое |
| Конструктор программ | модули, циклы, оценка времени, загрузка в стенд, общая библиотека |
| Скорость и ток во времени | график (скорость со знаком: + по часовой) |
| Журнал событий | события стенда, команды, действия других операторов; архив в CSV |

E-STOP работает **без права управления**: остановить вал должен мочь любой, кто
видит панель. Остальные команды уходят только от владельца канала.

## Конструктор программ

Программа - это список **модулей**, который повторяется заданное число **циклов**.
Модуль: направление (↻ CW / ↺ CCW), сколько оборотов, скорость (об/мин), пауза
после модуля (с). Модули добавляются (`+ Модуль` копирует последний,
`+ Туда-обратно` добавляет пару CW/CCW с паузами), переставляются ↑↓,
дублируются ⧉ и удаляются ✕.

- **Склейка**: модуль с паузой 0, за которым идёт модуль в ту же сторону (в том
  числе первый модуль следующего цикла), помечен «⟶» - стенд проходит границу без
  остановки, плавно меняя скорость. Так собираются профили скорости.
- **Полоса цикла** показывает модули в масштабе времени (синий - CW, зелёный - CCW,
  штриховка - паузы). Сводка - обороты за цикл (по направлениям), всего, оценка
  длительности цикла и программы с учётом рампы.
- **Загрузить в стенд** / **Загрузить и запустить** - программа уходит в стенд
  (`POST /v1/program`) и хранится в его памяти; возможно только когда вал стоит.
  Тег «загружена в стенд» показывает, что открытая программа совпадает с
  загруженной.
- **Библиотека** - общая для всех операторов (на сервере панели, файл
  `data/programs.json`): открыть, сохранить, сохранить как новую, удалить (с
  подтверждением). Плюс экспорт/импорт JSON и «Открыть из стенда».
- Черновик живёт в браузере (`localStorage`) и переживает перезагрузку страницы.

Проверки повторяют прошивку: до 64 модулей, 0,01…1 000 000 оборотов,
0,1…200 об/мин, пауза до 1 часа, до 1 000 000 циклов.

## Адрес стенда

Как у других панелей: поле в шапке → `localStorage["rotate.stand_host"]` →
`VITE_STAND_HOST` из `.env` → `1.rotate.esp32-s3.local`. Если `.local` не
резолвится, впишите IP стенда (печатается в Serial при загрузке).

## Разработка и проверка без железа

```bash
npm install
```

```bash
npm run dev
```

Панель - `http://localhost:5175` (API координации встроен в dev-сервер Vite).
Для проверки без стенда есть симулятор с тем же протоколом (рампа, программы,
склейка, пауза, ток):

```bash
npm run sim
```

и в шапке панели адрес `localhost:8090`.

## Сервер координации

`server/api.mjs` - тот же канал управления и журнал, что у dashboard1/2, плюс
библиотека программ:

- `GET /api/programs` - список;
- `POST /api/programs` - `{ program: {id?, name, cycles, modules}, user, host }`
  (с `id` - обновить, без - создать);
- `DELETE /api/programs/<id>?user=&host=`.

Сохранение и удаление пишутся в общий журнал и видны другим операторам стенда.

Переменные окружения - как у dashboard1/2, плюс `DATA_DIR` (каталог библиотеки,
по умолчанию `./data`).

## Сборка и деплой

```bash
npm run build
```

```bash
docker compose up -d --build
```

Контейнер `dashboard3`, порт 5175, тома `./logs` и `./data`, сеть `tmvos`. Для
публикации на шлюзе `http://tmvos.panel/rotate/`:

- `deploy/rotate.conf` → `mainpage/nginx/apps/`, перезагрузить nginx;
- `deploy/portal-app.json` → добавить в `mainpage/portal/apps.json` (вписать IP
  стенда).

## Соответствие прошивке

`src/types.ts` повторяет JSON `firmware/src/Telemetry.cpp`, `src/standLogic.ts` -
переходы `Controller.cpp`, `src/config.ts` (`LIMITS`) и `programLogic.ts` - пределы
`Config.h`. При изменении прошивки эти места держать в синхроне. Симулятор
`tools/stand-sim.mjs` - тоже.
